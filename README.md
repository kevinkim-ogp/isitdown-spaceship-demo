# Service Status Tracker

A real-time downdetector for Singapore government authentication services, built by [Open Government Products](https://open.gov.sg).

## Overview

Service Status Tracker allows public officers to report and view issues with government authentication services (Plumber, SingPass, CorpPass). Officers can report issues when logged in, while anyone can view the current status dashboard without authentication.

## Features

### Public Dashboard (No Authentication)
- 📊 Real-time view of services with active issues
- 📈 Services sorted by number of reports
- 🔍 Issue type breakdown for each service
- ⏰ Last 24 hours of report data
- 🔄 Auto-refreshing status

### Issue Reporting (Authenticated)
- 🔐 Secure email OTP login
- 📝 Report issues with specific services
- 🏷️ Categorize issue types (login failures, OTP issues, slowness, etc.)
- 💬 Optional comments for additional context
- 🚫 Duplicate prevention (2-minute window)

### Follow-up System
- 📧 Automated 1-hour follow-up emails
- ✅ Confirm if issues persist or are resolved
- ⏳ Automatic expiry after 24 hours

## Tech Stack

- 🧙‍♂️ E2E typesafety with [tRPC](https://trpc.io)
- ⚡ Full-stack React with Next.js
- 🎨 ChakraUI for components
- 💾 DynamoDB for data storage
- 📧 Email notifications via Postman
- 🔐 Email OTP authentication

## Running the app

### Install dependencies

```bash
npm i
```

### Set environment variables

```bash
cp .env.example .env.development.local
```

Optionally set `POSTMAN_API_KEY` to send login OTP emails via [Postman](https://postman.gov.sg).
If not set, OTP emails will be logged to the console instead.

#### Retrieving client-side environment variables in code

⚠️ When adding client-only environment variables in NextJS, you must prefix the variable with `NEXT_PUBLIC_` to ensure that the variable is exposed to the browser. For example, if you want to add a variable called `MY_ENV_VAR`, you should add it to your `.env` file as `NEXT_PUBLIC_MY_ENV_VAR`.

You will also need to update [src/env.mjs](src/env.mjs#L17) to explicitly reference the variable so NextJS will correctly bundle the environment variable into the client-side bundle.

### Start server

```bash
npm run dev
```
